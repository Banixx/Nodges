# Nodges Schema 5.2

## Aktualisierungen und Änderungen
Das Datenschema wurde auf die Version 5.2 gehoben. Hier sind die entscheidenden Änderungen, die in diesem Schritt durchgesetzt wurden, um die Rendering-Fehler (wie z. B. fehlende Nodes bei temporalen Datensätzen) dauerhaft zu verhindern:

### 1. Flache Datenstruktur (`dataModel.properties`) erzwungen
Das Verschachteln von Properties unter `dataModel.entities.X.properties` oder `dataModel.relationships.X.properties` wurde aus dem Zod-Schema (`src/types.ts`) komplett entfernt.
Ab sofort ist ausschließlich eine **flache Definition** der Properties im Root des `dataModel` erlaubt:
```json
"dataModel": {
  "properties": {
    "label": { "type": "text" },
    "kategorie": { "type": "categorical", "values": ["A", "B"] }
  }
}
```
Die `SuggestionUI` wertet genau dieses flache Objekt aus. Das Fehlen dieser flachen Struktur war der Grund, weshalb die Automapping-Vorschläge leere Ergebnisse lieferten.

### 2. Standard-Schema Version
Die Metadaten-Eigenschaft `schemaVersion` hat in der Schema-Definition nun standardmäßig den Wert `"5.2"`.

## Zusammenfassung der generierten Dateien
* `src/types.ts`: Aktualisiert, um die Verschachtelungen aus `DataModelSchema` zu entfernen.
* `public/data/nodges_schema.json`: Das aktualisierte JSON-Schema, generiert durch den Vitest-Export-Test.
* `public/nodges_schema.json`: Das ebenfalls aktualisierte Root-Schema.

Jeder künftige LLM-Aufruf zur Generierung von temporalen Graphdaten muss sich strikt an diese flache Struktur in Version 5.2 halten.
