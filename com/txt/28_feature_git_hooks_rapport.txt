## 2. Ausgangslage & Benutzerbeschluss

### 2.1 Der Benutzerbeschluss
Der Benutzer hat verbindlich vorgegeben:
1. **Feature-Standard:** Jedes Vorhaben wird ab jetzt immer mit einem neuen Ordner unter `com/feature/`, Multi-Harness-Rapport und One-Page-Dashboard eingerichtet. Vor dem Launch erfolgt die Multi-Harness-Abstimmung.
2. **Git-Hooks & Push-Regel:**
   - Git-Hooks (`pre-commit`, `pre-push`, `post-commit`) muessen aktiv greifen.
   - **Ein Push nach GitHub darf AUSSCHLIESSLICH bei Major-Versionen (`X.0.0`) erfolgen.**
   - Minor-Versionen (`0.X.0`) und Patch-Versionen (`0.0.X`) duerfen **NICHT** nach GitHub gepusht werden.
   - Selbst bei einer Major-Version darf der Push **NUR NACH EXPLIZITER RUECKFRAGE AN DEN BENUTZER** ausgefuehrt werden.

### 2.2 Analyse des Ist-Zustands
1. **`git-hooks/pre-push`:**
   - Aktuell blockierte Zeile 22 nur Patch-Versionen.
   - Minor-Versionen (`patch == 0`, z.B. `0.107.0`) wurden ungeprueft durchgewunken.
2. **`tools/nodges-git.sh`:**
   - Der Befehl `release` machte frueher automatisch einen Push nach GitHub.
3. **`tools/nodges-git-version.mjs`:**
   - Bietet bisher nur `bump patch` und `bump minor`. Ein `bump major` fehlte bisher.
4. **Git-Hooks Aktivierung:**
   - `core.hooksPath = git-hooks` muss fuer conT und piCon aktiv sein.

## 3. Ziel-Architektur & Spezifikation

### 3.1 Anpassung in `git-hooks/pre-push`
- Version aus `HEAD:package.json` wird geprueft (`minor` und `patch`).
- Wenn `minor != 0` ODER `patch != 0`: PUSH WIRD BLOCKIERT.
- Nur wenn `minor == 0` UND `patch == 0` (Format `X.0.0`) ist ein Push grundsaetzlich erlaubt.
- Notfall-Override bleibt weiterhin `NODGES_ALLOW_PUSH=1`.

### 3.2 Anpassung in `tools/nodges-git-version.mjs`
- Unterstuetzung fuer `bump major` (`${haupt + 1}.0.0`).
- Pruefung fuer Major-Release (`check-major`: prueft ob `minor === 0 && patch === 0`).

### 3.3 Anpassung in `tools/nodges-git.sh`
- `save`: Patch-Zwischenschritt (`0.0.X`), lokaler Commit, kein Push. **Erfolgt selbststaendig durch Agenten.**
- `release`: Minor-Meilenstein (`0.X.0`), Tests, lokaler Commit, lokales Tag. **KEIN PUSH. NUR NACH RUECKSPRACHE MIT DEM BENUTZER** (`--bestaetigt-durch-user`).
- `major`: Major-Release (`X.0.0`), Tests, Commit, Tag, Push nach GitHub. **NUR NACH RUECKFRAGE AN DEN BENUTZER** (`--bestaetigt-durch-user`).
